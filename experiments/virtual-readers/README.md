> **수치는 오락용 가정이며 시장 예측이 아니다.** 원고를 쓰거나 만들지 않는다. 외부 API·네트워크·난수·현재 시각을 쓰지 않는다. 입력은 검증 계획 예제의 수동 태그뿐이다.

- **결정 상태:** D01(실험 착수와 범위)·D06(가상 독자의 범위)은 계속 **대기**다. 이 실험은 그 결정의 판단 자료일 뿐 결정이 아니다([decisions.md](../../docs/decisions.md)).
- **기준:** 노션 [PoC 검증 계획 · 합성 원고와 독자 지표 검산 v0.1](https://app.notion.com/p/420cd7a6269781c29f66c15683709c34)의 "가상 독자 2집단 검산"과 사례 V10, 2026-11-22T01:44Z 편집본. 이 예제는 기술 검토 [6.3–6.4절](../../docs/reviews/tech-review-claude-v0.1.md)을 검토하기 위한 가정값이다.

## 계산식

검증 계획의 식을 그대로 옮겼다. 집단마다 회차 순서대로 계산한다. 강도 I는 0–3이고 입력에 없는 태그는 0이다.

```
x = Σ 가중치 × 강도                                   (회차 기여도)
F = clamp(0.6·F′ + max(0, −w_G·I_G) − 0.15·I_C, 0, 3)   (불만)
S = clamp(0.5·S′ + 1 + x − 0.5·F, 0, 4)                (만족, F는 이번 회차 값)
T = clamp(T′ − 0.25·I_B·s + 0.1·I_R, 0, 1)             (신뢰, s = 배신 민감도: 순애 1, 피폐 0)
p = b + (1 − b)·σ(2·(0.15 − S − 0.5·T)),  σ(z) = 1/(1 + e^−z)
N = N′·(1 − p)                                       (기대 잔류 인원, 중간 반올림 없음)

누적 잔존율 = 이번 합계 ÷ 초기 합계
연속 열람률 = 이번 합계 ÷ 직전 합계 (1화의 직전 합계는 초기 합계)
분모가 0이면 그 비율은 "해당 없음"
```

## 미해결 계산 가정

PoC가 표를 재현하려고 고른 해석이다. 확정이 아니다.

### 기획 확인이 필요한 것

1. **배신 민감도.** 계획 식의 "순애 집단 지시값"을 집단 매개변수 `betrayalTrustSensitivity`(순애 1, 피폐 0)로 두었다. 0–1 사이 소수도 받는다. 이름, 소수를 허용할지, 새 집단의 기본값이 정해지지 않았다.
2. **태그 강도와 목록.** 강도는 0–3 실수다(기술 검토 6.2의 0~3). 정수만 허용할지는 미정이다. 태그는 예제의 5종(G·B·C·R·H)으로 닫아 두었고 전체 분류표는 기획 영역이다.
3. **G의 불만 기여.** `max(0, −w_G·I_G)`라서 G 가중치가 양수인 집단(피폐)은 G로 불만이 생기지 않는다. 그래도 G는 기여도 x에 그대로 들어가 그 집단의 만족을 올린다. 의도한 동작인지 확인이 필요하다.
4. **집단 공통 상수.** C의 불만 해소(0.15), R의 신뢰 상승(0.1), 감쇠·임계값(0.15)·기준선 항(1)이 모든 집단에 같다. 기술 검토 6.3의 집단별 θ_c·기준선_c는 이 예제에서 하나로 고정된다.
5. **기본 이탈 하한 b.** 회차마다 입력으로 받는다. 기술 검토 6.3의 기본 이탈 곡선은 없고, 실측 근거가 없는 조정값이다.
6. **소수 인원 표시.** 기대 인원은 소수 그대로 계산하고 4자리로 표시한다. 화면에 정수로 보일지 정하지 않았다. 반올림한 집단 값의 합이 반올림한 전체와 다를 수 있다(예: 1.00004 + 1.00004는 각각 1.0000이지만 전체는 2.0001). V10 예제에서는 네 회차 모두 일치한다.
7. **비율은 전체 기준만.** 누적 잔존율과 연속 열람률은 계획 정의대로 전체 합계로만 계산한다. 집단별 비율은 정의하지 않았다.
8. **반사실의 범위와 이탈 사유.** 반사실은 같은 직전 상태에서 한 회차만 바꿔 그 회차 이탈률을 비교한다. 이후 회차로 퍼지는 효과는 계산하지 않는다. 여러 태그의 효과는 더해지지 않는다. 3화 순애에서 C만 빼면 이탈이 4.6284%p, R만 빼면 0.6448%p 늘지만 둘 다 빼면 7.3041%p 늘어 두 값의 합(5.2732%p)과 다르다. 그래서 기술 검토 6.3의 "이탈의 62%는 관계 배신" 같은 태그별 비율 설명은 먼저 귀속 방법(한 태그씩 빼기, 섀플리 값 등)을 정해야 한다.
9. **섭동·민감도·유입.** 시드 섭동(기술 검토 6.4), 12개 비교 쌍과 공통 시드 20개의 민감도 검사, 유입은 구현하지 않았다. 스냅샷에는 섭동·난수 알고리즘·시드를 `null`로 남긴다. 12개 비교 쌍의 구성과 섭동 대상·크기는 계획에서 아직 정해지지 않았다.
10. **판본 ID·약속 프로필.** 계획은 실행 기록에 판본 ID 순서와 약속 프로필도 저장하라고 한다. 이 예제 입력에는 둘 다 없어 회차 순서만 입력에 들어간다. 실제 원고와 연결할 때 스냅샷에 넣어야 한다.
11. **가중치 범위.** 기획상 범위가 없다. 계산 안전을 위해 절댓값 1e6까지만 받는다(구현 선택 2).

### 구현 선택 (검토용)

1. **범위 밖 입력은 거부.** 초기 상태가 clamp 범위 밖이거나 강도가 0–3 밖, b가 0–1 밖이면 값을 고쳐 계산하지 않고 `InputError`(코드·위치)로 거부한다. clamp는 계산 중에만 쓴다.
2. **계산 안전 한계.** 인원과 그 합계는 2^53−1 이하, 가중치 절댓값은 1e6 이하, 집단 id·이름은 1–64자다. 계산이 넘치거나 NaN이 되지 않게 하는 공학적 한계이고 계획 값이 아니다.
3. **부동소수 재현 범위.** 같은 입력이면 같은 JavaScript 엔진(같은 Node 버전)에서 비트 단위로 같다. `Math.exp`는 엔진마다 마지막 자리가 다를 수 있어 다른 엔진이나 언어와는 비트 동일을 보장하지 않는다. 그 비교에는 허용오차를 쓴다.
4. **합계 순서와 해시 정규화.** 합계는 집단 id 순서로 더한다. 집단이 셋 이상이면 덧셈 순서가 결과 비트를 바꿀 수 있기 때문이다. 입력 해시는 집단을 id 순으로 정렬하고, 적지 않은 태그를 0으로 채우고, 커널 버전·상수를 넣어 계산한다. 표시 이름도 해시에 들어간다. 예제나 커널 상수가 바뀌면 동결 해시 테스트가 실패한다.
5. **표시 반올림.** 4자리, 배정밀도 값 기준 가장 가까운 쪽, 정확히 가운데면 0에서 먼 쪽(`toFixed`)이다. −0은 0으로 쓴다. 이 규칙으로 계획 표가 글자까지 재현된다. 다른 언어로 옮길 때도 같은 규칙이 필요하다.
6. **V10 중 이 PoC 밖의 항목.** 댓글·캐시 계층이 없어 "댓글을 끈 캐시 적중 20회 외부 호출 0회"는 해당하지 않는다. 20회 반복 계산의 외부 호출 0회만 확인했다.
