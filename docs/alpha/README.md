# 감떨 알파 (개인 검증용)

- **주소:** https://suminseong.github.io/gamddeol/
- **승인:** 참깨빙수, 2026-11-22. 알파 구현과 GitHub Pages 배포.
- **성격:** 참깨 개인 검증용 알파. 감평 품질은 평가하지 않는다. 기본 UI가 동작하는지, 다음 기능을 붙일 수 있는 구조인지를 본다.

한 화면에서 OpenAI API 키를 등록하고, 원고를 평문으로 쓰거나 붙여넣은 뒤 **감평 실행**을 누르면 OpenAI 응답 텍스트를 보여 준다.

## 범위

| 포함 | 제외 (이번 알파에서 만들지 않음) |
|---|---|
| 키 입력·등록·지우기 (탭 메모리만) | 파일 업로드 |
| 줄바꿈이 보존되는 평문 원고 입력 | 서식 에디터 |
| 감평 실행, 진행 표시, 취소 | 자동 저장 |
| 결과 표시, 오류 안내, 다시 시도 | 계정·DB·별도 서버 |
| 빈 입력·중복 실행 차단 | 페르소나·위키 |

## 쓰는 법

1. 위 주소를 연다. 공용·공유 컴퓨터에서는 쓰지 않는다.
2. **OpenAI API 키**에 키를 넣고 **등록**을 누른다. 등록만으로는 아무 요청도 나가지 않는다. 사용 한도를 낮게 둔 검증용 키를 따로 만들어 쓰기를 권한다.
3. **원고 (평문)**에 원고를 쓰거나 붙여넣는다.
4. 실행 버튼 위의 전송 고지(어디로 무엇을 보내는지)를 확인하고 **감평 실행**을 누른다.
5. 오른쪽(좁은 화면에서는 아래) **감평 결과**에서 응답을 확인한다.
6. 끝나면 **지우기**를 누르거나 탭을 닫는다. 검증이 끝난 키는 OpenAI 대시보드에서 폐기하기를 권한다.

### 실호출 검증 통과 기준

감평 결과 영역에 다음이 모두 보이면 통과다.

- **OpenAI 응답** 배지
- `resp_`로 시작하는 응답 ID, 모델 이름, 토큰 수
- OpenAI가 보낸 감평 텍스트

**모의 응답** 배지는 배포 주소에 나오지 않는다. 자동 검증의 네트워크 모의 응답은 `[네트워크 모의 응답]` 문구로 시작해 실제 응답과 구분된다.

### 결과를 알려 줄 때

- 성공했는지, 실패했다면 화면의 **오류 제목과 HTTP 상태**만 알려 준다. 예: `인증 실패 (401)`. 쓴 브라우저 이름도 함께 적는다.
- 키, 원고, 감평 결과 본문, 화면 캡처는 채팅·이슈·PR에 올리지 않는다.
- 화면의 **OpenAI 메시지** 원문도 옮기지 않는다. 401 메시지에는 키 일부가 가려진 형태로 들어 있을 수 있다.

## 무엇이 어디로 가는가

**감평 실행**을 누를 때만, 다음 요청 하나를 OpenAI 공식 엔드포인트 한 곳으로 보낸다.

| 항목 | 위치 | 값 |
|---|---|---|
| 주소 | | `POST https://api.openai.com/v1/responses` |
| API 키 | `Authorization` 헤더 | `Bearer <등록한 키>` |
| 원고 | 요청 본문 `input` | 입력한 원고 그대로 |
| 감평 지시 | 요청 본문 `instructions` | [src/review/config.ts](../../src/review/config.ts)의 지시문 |
| 설정 | 요청 본문 | `model`, `max_output_tokens`, `reasoning.effort`, `store: false` |

- 그 밖에 페이지가 불러오는 것은 같은 주소(`/gamddeol/`) 아래 페이지 자체 파일뿐이다. 외부 글꼴, 분석 도구, 광고, CDN, 외부 스크립트는 없다.
- 페이지의 콘텐츠 보안 정책(CSP)이 `connect-src`를 위 엔드포인트 하나로 묶는다. 코드가 다른 곳으로 요청을 보내려 해도 브라우저가 막는다.
- 요청은 리디렉션을 따라가지 않고(`redirect: 'error'`), 쿠키(`credentials: 'omit'`)와 리퍼러(`no-referrer`)를 보내지 않는다.
- 다른 서버, 프록시, 대체 엔드포인트는 쓰지 않는다.

## 남기지 않는 것

- **키:** 비밀번호형 입력칸에 넣고 등록하면 입력칸은 바로 비우고, 키는 이 탭의 메모리(자바스크립트 변수)에만 둔다. **지우기**, 새로고침, 탭 닫기, 페이지 이동 때 사라진다.
- **원고와 결과:** 화면 상태(탭 메모리)에만 있고 새로고침하면 사라진다.
- localStorage, sessionStorage, IndexedDB, 쿠키, Cache Storage, URL, 콘솔에 쓰지 않는다. 다음 세 가지로 확인한다.
  - 단위 테스트의 소스 검사
  - 빌드 후 배포 파일 검사
  - E2E의 브라우저 저장소 검사
- 배포 파일에 소스맵을 넣지 않는다. 모의 전송 코드도 배포 번들에서 빠진다.
- 자동 검증은 가짜 키(`sk-uitest-FAKE-…`), 원고가 아닌 짧은 UI 검사 문자열, 네트워크 모의 응답만 쓴다. 저장소, Actions, 배포 파일 어디에도 실제 키와 원고가 없다.

## 알려진 한계와 주의

- **브라우저에서 키를 직접 쓴다.** OpenAI는 API 키를 브라우저나 모바일 앱 같은 클라이언트 환경에 두지 말고 자체 서버를 거쳐 쓰라고 권고한다([OpenAI 도움말: API 키 안전 수칙](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety)). 이 알파는 그 권고를 알고 참깨 개인 검증용으로만 쓴다. 여러 사람이 쓰는 기능으로 넓히려면 서버를 거치는 구조로 바꿔야 한다.
- **브라우저 확장 프로그램:** 같은 탭에서 도는 확장 프로그램은 페이지 입력을 읽을 수 있다. 확장 프로그램이 적은 브라우저 프로필에서 쓰기를 권한다.
- **비밀번호 관리자:** 입력칸에 저장 제외 속성을 달았지만 모든 관리자가 따르지는 않는다. 저장을 제안하면 저장하지 않는다.
- **store: false:** OpenAI에 응답 객체를 저장하지 말라고 요청하는 값이다. 그 밖의 보존(예: 악용 모니터링)은 OpenAI 정책을 따른다.
- **브라우저 직접 호출(CORS):** OpenAI가 브라우저 호출을 허용해야 동작한다. 배포 후 검증이 가짜 키로 실제 엔드포인트를 한 번 불러 확인하고, 결과를 Actions 실행 요약에 남긴다(아래 "배포" 참고). 가짜 키로는 사전 확인과 401 응답까지만 확인되므로 최종 확인은 참깨의 실호출이다.
- **모델 접근:** 키가 속한 OpenAI 프로젝트가 설정된 모델을 쓸 수 없으면 `권한 없음 (403)`이나 `모델을 찾을 수 없음 (404)`이 나온다. 모델은 [src/review/config.ts](../../src/review/config.ts)에서 바꾼다.
- **길이와 시간:** 원고는 최대 200,000자, 응답 대기는 3분, 출력 상한은 4,000 토큰이다. 출력 상한에는 추론 토큰도 들어간다. 상한에 걸려 응답이 끊기면 화면에 알린다. 원고가 모델 한도를 넘으면 `요청 오류 (400)`이 나온다.
- **CSP는 meta 태그로 건다.** GitHub Pages는 응답 헤더를 바꿀 수 없어서다. meta CSP는 `frame-ancestors`를 지원하지 않으므로, 다른 사이트의 iframe 안에서는 스크립트가 화면을 띄우지 않는다.

## 브라우저 직접 호출이 막혔을 때

화면에 `네트워크 오류 또는 브라우저 차단`이 나오는 경우다.

1. 인터넷 연결을 확인한다. 확장 프로그램을 끈 프로필이나 다른 브라우저로 다시 시도한다.
2. 최근 Pages 실행 요약의 "OpenAI 브라우저 호출 확인(가짜 키)" 결과를 본다. `reachable`이면 OpenAI가 브라우저 호출을 허용하고 있다는 뜻이다. 그렇다면 참깨 쪽 환경(확장 프로그램, 보안 프로그램, 네트워크)을 먼저 의심한다.
3. 개발자 도구 콘솔에 CORS 관련 메시지가 있는지 본다.

**우회 서버나 프록시를 붙이지 않는다.** 원인과 재현 조건을 기록한다. 키나 원고 없이 다음 항목만 적는다.

- 브라우저와 버전
- 시각
- 화면 표시
- probe 결과
- 콘솔 메시지 요지

## 구조

화면, 감평 요청·결과, OpenAI 전송을 분리했다. 화면은 감평 서비스만 알고, 감평 서비스는 `Transport` 인터페이스만 안다.

```
src/
  main.tsx              조립 지점. 실제 전송과 모의 전송 중 하나를 고르고 키 세션을 만든다
  app/                  화면 (React)
    App.tsx             한 화면 구성, 실행 가능 여부 판단
    useReviewRunner.ts  실행 상태(대기·진행·성공·오류), 중복 실행 차단, 취소
    copy.ts             화면 문구 전부 (알파용 초안, UX 라이팅은 디자인 담당이 다듬는다)
    components/         KeyPanel · ManuscriptPanel · RunPanel · ResultPanel · SecurityNotice · MockBanner
  review/               감평 요청·결과 (네트워크를 모른다)
    config.ts           모델·감평 지시·출력 상한·시간 제한·원고 길이 상한 ← 바꿀 곳은 여기 하나
    buildRequest.ts     요청 본문 생성
    parseResponse.ts    응답 해석 (텍스트, 끊김, 거절, 빈 응답)
    errors.ts           HTTP 상태와 전송 실패를 오류 종류로 바꾼다
    reviewService.ts    입력 검사 → 요청 생성 → 전송 → 해석
  transport/            OpenAI 전송 (fetch는 openaiTransport.ts 한 곳에서만 쓴다)
    endpoint.ts         허용 엔드포인트 상수 (CSP도 이 값을 쓴다)
    openaiTransport.ts  실제 전송
    mockTransport.ts    네트워크 없는 모의 전송 (테스트·dev:mock 전용, 배포 번들에서 빠짐)
  session/keySession.ts 키를 탭 메모리에만 두는 저장소
  security/             CSP 생성, iframe 차단
```

다음 기능을 붙일 때는 이렇게 하면 된다.

- **파일 업로드:** 원고 입력원만 추가한다. 감평 서비스는 문자열만 받는다.
- **감평 종류 추가:** `ReviewConfig`를 여러 개로 늘린다.
- **서버 경유로 전환:** `Transport` 구현 하나만 바꾼다. 화면과 감평 코드는 그대로 둔다.

## 명령

Node 22(`.nvmrc`)가 필요하다. 실제 키나 원고 없이 모두 돈다.

```sh
npm ci
npm run dev        # http://127.0.0.1:5173/gamddeol/ (실제 OpenAI 전송)
npm run dev:mock   # 모의 모드: 네트워크를 쓰지 않고 시나리오(성공·401·429·시간 초과 등)를 골라 본다
npm run typecheck  # TypeScript 검사
npm test           # 단위·통합 테스트 (Vitest, 모의 전송)
npm run build      # dist/ 생성 후 배포 파일 검사 (scripts/verify-dist.mjs)
npm run e2e        # Playwright: 로컬 배포 빌드를 /gamddeol/ 경로로 띄워 네트워크 모의로 검사
npm run check      # 위 검사 전부
```

E2E를 처음 돌릴 때는 `npx playwright install chromium`으로 브라우저를 받는다.

빌드 후 배포 파일 검사가 확인하는 항목:

- CSP가 있고 `connect-src`가 엔드포인트 하나인지
- 인라인 스크립트가 없는지
- 모든 경로가 `/gamddeol/`로 시작하는지
- 모의 응답 문구, 브라우저 저장소 API, 소스맵이 없는지

## 배포

비밀값을 쓰지 않는다. 저장소 Secrets도 쓰지 않는다.

1. **PR**: [CI](../../.github/workflows/ci.yml)가 타입 검사, 단위·통합 테스트, 빌드와 배포 파일 검사, E2E를 돌린다.
2. **main에 머지**: [Pages](../../.github/workflows/pages.yml)가 다음 순서로 돈다.
   - **build:** 검사 후 빌드한다. 빌드 ID는 커밋 SHA이고 페이지 meta와 바닥글에 들어간다.
   - **deploy:** GitHub Pages에 올린다.
   - **verify:** 배포 주소를 검증한다.
     - 배포 주소가 이번 빌드를 내보낼 때까지 기다린다.
     - 배포 주소에서 E2E를 돌린다. 정적 리소스 로드, 새로고침, 모의 성공과 실패를 확인하고, 허용 목록 밖 요청이 없는지 본다.
     - 가짜 키로 실제 엔드포인트를 한 번 불러 브라우저 호출이 막히지 않는지 기록한다. 이 단계는 실패해도 배포를 되돌리지 않는다. 결과는 실행 요약에 JSON으로 남는다.
